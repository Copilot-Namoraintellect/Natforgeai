# WBS-R3.4 — GAP29 Launch/Package/Queue Edges Report

**Branch:** `recovery/r3-integrity-closure`
**Status:** CLOSED (three discontinuities fixed; package/queue identity verified against existing authority)

## Investigation summary

Verified call graph (unchanged from R1.7, re-confirmed against code):

- Distribution complete → `campaign_launch` request; decision ownership-scoped with
  in-transaction audit and post-commit `onApprovalResolved`.
- Approved → `enqueueApprovedPublishingRows` → deterministic BullMQ jobId.
- Package path: single caller, `publishing_queue` row + approved row persisted
  atomically (`content-router.ts` pack publish); `publishDuePosts`/`publishSinglePost`
  reload the durable package through the shared loader (WBS13.4).
- Execution: BullMQ worker and the 60 s fallback cron both funnel into
  `publishSinglePost`; `resolveExecutionDisposition` guards every entry; queue
  success is a guarded conditional UPDATE with idempotent-replay reread.
- Package identity, queue identity, crash-between-package-and-queue, and
  duplicate-retry protections are provided by the surviving WBS13 authority
  (`publish-package-queue-persistence`, deterministic BullMQ jobId, atomic
  pack persist, disposition guard) — verified by the existing WBS13.4 test
  suite; not reinvented here.

## Discontinuities fixed

### (a) Rejected launch left executable rows live — FIXED

`onApprovalResolved(campaign_launch, rejected)` only transitioned the
campaign. Distribution-created `approved` rows stayed executable: the
due-scan/BullMQ re-attempted them, failing closed at readiness each cycle and
churning durable rows toward terminal `failed`.

Fix: `withdrawApprovedPublishingRows` (triggers.ts) — campaign-scoped rows in
`approved` or `retrying` are parked to `pending_approval` +
`approvalRequired: true` (the established gated, non-executable authority
state — mirrors the brand_risk reject policy), and any scheduled BullMQ jobs
are cancelled best-effort (`removePublishingJob`). Terminal (`published`) and
already-gated rows are untouched; other campaigns are out of scope.

### (b/c) Immediate (NULL scheduledAt) approved rows had no BullMQ-independent executor — FIXED

Only launch-resolution enqueue could execute an approved row with NULL
`scheduledAt`; a BullMQ outage at that moment stalled it forever
(`lte(scheduledAt, now)` never matches NULL), and `publishing-router`
immediate rows (approved at creation; `approvePost` immediate re-approvals)
stalled even with BullMQ up because nothing ever enqueued them.

Fix: `publishDuePosts` now also selects approved + NULL-scheduledAt rows for
campaigns holding publication authority (`LIVE_PUBLICATION_WORKFLOW_STATES`,
mirroring the triggers.ts gate) via `buildImmediatePostsCondition`, and
executes the union with per-id dedupe. The campaign-authority gate is
load-bearing: pre-launch `approved`-but-unscheduled rows (the brand_risk
approval design) stay invisible — otherwise the cron would park them in
`pending_approval` through the approval-blocked recovery path and the later
launch enqueue would skip them. Execution idempotency is unchanged (single
executor + disposition guard).

## Required-outcome checklist

- Approved launch cannot bypass durable package authority — unchanged; WBS13
  package binding + readiness validator still gate every execution.
- Package identity stable/idempotent — existing WBS13 authority (verified).
- Queue identity stable/idempotent — deterministic BullMQ jobId + guarded
  status UPDATE (verified); immediate-row scan dedupes by row id.
- Crash between package creation and queue insertion — existing atomic pack
  persist (verified).
- Duplicate retries cannot duplicate launches/publications — disposition
  guard + deterministic jobId (verified); withdraw prevents post-rejection
  attempts.
- Queue consumers validate durable authority before execution — unchanged
  (canonical validator; new cron rows are pre-filtered by campaign authority).
- Rejected/incomplete authority fails closed — strengthened: rejected launch
  now withdraws executable rows instead of relying on per-attempt readiness
  failure.
