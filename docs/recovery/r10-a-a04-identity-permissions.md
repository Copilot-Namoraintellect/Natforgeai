## 2. Identity model

Labels are proposed role names, not provisioned Windows account names or SIDs. Separate tokens and credentials are required where privileges differ; a new label on the same token is not isolation. Account technology (local service account, supported virtual/service SID, or domain-managed account if available) remains D05; do not assume a domain or gMSA prerequisite is satisfied.

Password rotation, non-interactive credential delivery, profile loading and service-logon rights must be compatible with the eventual supervisor. ## 3. Filesystem ACL design and inheritance boundary

Only `D:\www\natforgeai` exists. Proposed relative paths below are logical scopes, not an approved final directory layout. Backup storage must be **outside the application root and every web-served path**, with a separately approved location. Configuration, credentials, service control and mutable data must not share an inherited common Modify grant.

Permission legend: `-` = no application-specific grant, with effective access to be proved absent; `T` = minimum traverse/read-attributes on containers only; `R` = read/list only; `RX` = read/execute approved binaries or directory traversal (no script-upload execution authorization); `W` = scoped create/update without DACL/owner/control change; `M` = scoped data modification including required rename/delete; `A` = append/create-log capability subject to logging design; `S` = read only a role-specific redacted view or owned subdirectory; `C` = controlled administrative operation; `F` = administrative full control, not a routine runtime grant. These are semantic requirements, not literal generic NTFS ACE masks. Parent access does not mean recursive child access.

IA and approved SYSTEM maintenance retain administrative control on NatForgeAI scopes; LEGACY's current admin capability is not expressible as an enforceable `-` denial and is addressed separately. MIG/STOP receive no general filesystem grant except their dedicated credential/control scopes listed below. Existing Zuto/other pool identities, broad Users/Authenticated Users/Everyone/IIS_IUSRS grants and unrelated CI identities are omitted from NatForgeAI grants; actual group-derived rights must still be measured.

`R own` never means access to another role's credentials. A single generic `shared` grant would defeat these partitions. Application processes need read/execute access to the installed Node binary and approved fixed native tools, not write access to their install directories or unrestricted execution from uploads/scratch. NTFS data write and code-execution prevention are separate controls: an arbitrary-code runtime can interpret writable data; do not claim a folder ACE alone prevents all execution.

### NatForgeAI-only inheritance proposal

Later authorized provisioning must inventory owner/DACL/SACL/inheritance and effective tokens first, preserve an administrative recovery copy, then protect the NatForgeAI root and each differing security boundary with explicit minimal ACEs. Do not copy inherited broad Users grants into an equally broad explicit ACL. Review CREATOR OWNER/OWNER RIGHTS, object/container inheritance and inherit-only flags; precreate/seal protected directories with controlled ownership. New/moved/restored files can carry different descriptors, so evaluate final effective ACLs after deployment and restore rather than assuming a move re-inherits the target policy. Windows distinguishes creation and move behavior. [Microsoft file security](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)

Do **not** put a blanket explicit Deny on BUILTIN\Users: legitimate dedicated local service accounts may also be members. Prefer explicit scoped allows and removal of inappropriate inherited grants inside the authorized subtree, with reviewed narrow denies only if necessary. Never recursively reset ACLs from `D:\www`, follow reparse points outside the approved boundary or alter Zuto ACLs. Validate resolved targets, volume/junction links, child ownership and inheritance propagation. The `icacls` documentation distinguishes these controls; no command was run. [Microsoft ACL reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls)

Exact inherited rights are UNKNOWN. Parent delete-child rights can permit deletion independently of a child object's delete grant; subtree inheritance isolation alone therefore does not prove root protection. File deletion has this alternate parent-rights path. [Microsoft deletion access rules](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-deletefilew) A later effective-access drill must check parent deletion/rename/replacement routes, including directory-specific behavior. If existing `D:\www` permissions permit such interference and a safe solution requires changing that parent, stop: parent/Zuto ACL changes are outside this scope and need a separately approved architecture exception (for example an independently secured root). Do not silently repair the parent or certify containment. Protected root ownership is also not containment against I01/I11 administrative takeover.

Objects created by runtime may be runtime-owned; custom write ACEs alone do not prove the owner cannot change their DACL. Review owner semantics before asserting deny guarantees. Release files, stop state, service configuration, secrets and independent audit must be pre-owned by a trusted non-runtime authority. Append-only audit guarantees require a protected remote/DB/log sink and appropriate ownership/privileges, not just `A` in this matrix. Runtime-writable media remains a compromise/integrity risk and must not become executable config or backup-control input.

SCM start/stop/query, service configuration and service DACL/ownership are separate rights. Runtime must not have SERVICE_CHANGE_CONFIG or writes to service image path/wrapper/config, even if service-status query is allowed. Restart delegation must identify exact services and accepted control operations; no arbitrary command arguments, scripts or user-selected executable paths. [Microsoft service rights](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights)

DB/Redis proposals are not executable GRANT/ACL commands. The frozen app uses one configured `DATABASE_URL`/`REDIS_URL` per process; it does not prove separate H administration/runtime pools or a read-only monitoring connection. Explicit table/procedure/command/key allowlists require application/store inventory and B/F/X review, including legitimate lifecycle updates versus immutable records. Redis commands such as arbitrary scripts, CONFIG, ACL, FLUSH*, broad keys and PUBSUB/SCAN need exact justification; BullMQ uses scripting and queue operations, so blindly denying all scripts is not a validated worker policy. Use dedicated endpoints/instances where a safe command/key boundary cannot be proved. Monitoring must not see queue business payloads by acquiring a broad runtime Redis token.

G backup needs a dedicated dump connection, but F's application broker does not grant backup the DATABASE_SECRET reader class. Do not widen that broker: resolve dedicated backup connection credential handling in the independent backup context with F/G/X; classify its source explicitly and keep runtime DB credentials out. G encryption/offsite credentials belong to the backup job, not ND or application files. The dump tool's minimum metadata/locking privilege depends on chosen MySQL/version/settings; unresolved until reviewed. Restore authority and destructive offsite retention overrides remain separate, audited and independently protected.

## 5. Deployment, IIS and independent-stop separation

The proposed ND account is not the existing administrator deployer under a new label. A pipeline executing as I11 can change files, ACLs, wrappers and service identities, read local process secrets and affect Zuto. A dedicated non-admin ND token helps only if actual NatForgeAI steps run under that token and the administrative parent/agent cannot arbitrarily replace the trusted boundary; merely spawning a non-admin child does not contain its privileged parent. Select a dedicated constrained agent/promotion service or reviewed administrator-mediated deployment boundary under D02/D05/D07/D12. Its validator/publisher owns sealed releases and service selection; ND can supply artifacts but cannot rewrite validators, service commands or stop policy. Artifact signing/pinning and approval protect authorized deployment, but compromised promoted application code can use its runtime secrets; least privilege does not eliminate software-supply-chain trust.

No global Azure agent account/group change is authorized here. Do not remove the existing deployer from Administrators or change its Zuto jobs. Record continued administrative access as residual host trust; independently protected offsite copies and incident administration must not depend on that single local credential. Any need for a stronger separation than a shared administrator-controlled host is an unresolved architecture decision, not an ACL guarantee.

IIS uses a dedicated NatForgeAI pool virtual SID and hostname/SNI binding; no permission granted to the general IIS_IUSRS group or Zuto pool identities. Verify anonymous-auth identity/physical-path access choice so IUSR does not unexpectedly supply broad shared access. The pool's Windows identity applies to its IIS worker process; separately supervised Node API/worker processes use their own service logon tokens. A reverse proxy does not impersonate the pool into Node. [Microsoft pool identity model](https://learn.microsoft.com/en-us/iis/manage/configuring-security/application-pool-identities)

Loopback 3001 limits external listening but does not authenticate the calling local process: Zuto/other local code could attempt it. Preserve application auth/tenant checks and review proxy-header trust; do not assert the pool SID alone authorizes API calls. TLS certificate private keys remain under reviewed IIS/HTTP.sys/certificate-renewal access, not Node/ND credentials. Existing win-acme/Zuto renewal identities and ACLs remain unchanged; NatForgeAI certificate issuance and renewal scope are still future gates.

H requires runtime-unwritable independent stop and independently authorized H administration. For a file-based proposal, STOP owns the state and its parent, runtime gets status-read only, and no runtime ancestor DELETE_CHILD/rename/replace/reparse route may bypass it; alternative service/store control needs equivalent authorization. The mechanism is not chosen. No runtime service-control, release-selector, wrapper/config, credential/admin-pool or DACL write can allow self-restoration. H runtime `downgrade`, `enterSafeMode` and `gate` remain separate from admin methods; unavailable stop evidence denies. Independent stop service must not load runtime-writable binaries/config. Process restart, deployment completion or recovered health never clears H latches. Same-host administrators remain technically privileged; independent approval and out-of-host protection are needed where the threat model requires it.
