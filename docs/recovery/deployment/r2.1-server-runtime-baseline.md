# WBS-R2.1 — Server / Runtime Rebuild Baseline (Windows Server)

**Branch:** `recovery/r2-production-activation` · **Evidence:** repository sources as cited inline. This runbook describes how to rebuild NatForgeAI on a fresh Windows Server **from the repository alone** — nothing here has been executed against any server.

---

## 2. Scheduled / background processes

| Process | Where started | Enabled |
|---|---|---|
| Publishing worker (BullMQ consumer) | `worker.ts` (or embedded in `boot.ts` when Redis configured) | production + Redis |
| Content-generation worker (BullMQ) | same | production + Redis |
| Publishing fallback runner (60s interval) | `boot.ts` when Redis is NOT configured | non-Redis deployments |
| Daily credit-renewal scheduler | `boot.ts` (always) | always |
| Post-live lifecycle reconciliation scheduler | `boot.ts`, flag-gated | `POST_LIVE_LIFECYCLE_ENABLED=true` (default OFF) |
| Post-live metrics observation scheduler | `boot.ts`, flag-gated | `POST_LIVE_METRICS_OBSERVATION_ENABLED=true` (default OFF) |

## 3. Dependencies

- **Database: MySQL** (drizzle-orm/mysql2, `mode: "planetscale"`), connection string `DATABASE_URL`. *Repository evidence says MySQL — not PostgreSQL.* Migrations via `drizzle-kit migrate` against `db/migrations` (canonical 27-migration chain, see R1.8).
- **Redis**: optional for basic boot (fallback runner), **required** for the publishing/content workers, creative-claim heartbeats, and the observation-scheduler lease. `api/lib/redis.ts` (`isRedisConfigured()` checks `REDIS_URL`).
- **ffmpeg-static / sharp / execa / playwright**: bundled at build time but excluded from the esbuild bundle (native binaries); the build expects them installed via npm in `node_modules`.

## 4. Filesystem / runtime directories (relative to app root)

| Path | Purpose |
|---|---|
| `dist/boot.js`, `dist/worker.js` | built runtime entry points |
| `dist/public/` | built SPA + `web.config` (IIS site root) |
| `data/public/generated/`, `data/public/uploads/` | **persistent media**, created at boot if missing (`api/lib/vite.ts:29-45`); must survive rebuilds — exclude from deploy overwrites |
| `.env` | environment loading via `dotenv/config` at process start (`api/lib/env.ts:1`) |
| `~/.pm2/logs/` | PM2 stdout/stderr logs (console.* output) |
| IIS `Logs/` | reverse-proxy + static access logs (site binding) |

## 5. Environment-variable loading

- `api/lib/env.ts` loads `.env` from the process working directory via `dotenv/config`; system environment variables take precedence.
- **Fail-closed in production**: `APP_SECRET`, `DATABASE_URL`, `FIREBASE_SERVICE_ACCOUNT` throw at startup when missing (`required()`, `api/lib/env.ts:5-14`).
- Client-side Firebase config is baked at build time from `VITE_FIREBASE_*` (Vite).

## 6. Health endpoints & verification

- There is **no plain HTTP `/health` route** in `api/boot.ts` (verified). Health is exposed through tRPC (`api/health-router.ts`):
  - `health.getSystemHealth` — **public** (system/DB/Redis surface);
  - `health.getQueueHealth`, `getAIUsageHealth`, `getPublishingHealth`, `getAlertSummary`, `listAlerts`, `acknowledgeAlert`, `resolveAlertCategory` — admin.
- `scripts/verify-deployment.mjs` validates `web.config` rewrite rules in `public/` and `dist/public/`, plus an optional HTTP media smoke test via `NATFORGE_SMOKE_URL`.
- Post-start checks: `pm2 status`, `pm2 logs natforgeai`, then an authenticated tRPC `health.getSystemHealth` call, then `node scripts/verify-deployment.mjs` with `NATFORGE_SMOKE_URL`.

## 7. Restart / recovery behaviour

- PM2 auto-restart on crash (`pm2 start … --name natforgeai`); `pm2 save` + `pm2 startup` (Windows: `pm2-windows-startup` / NSSM service wrapper) for reboot survival.
- `worker.ts` registers SIGINT/SIGTERM graceful shutdown (stops BullMQ workers); `boot.ts` schedulers are interval-based and die with the process.
- Recovery order after reboot: MySQL → Redis → PM2 resurrect (API + worker) → IIS (auto) → verify health.
- Rollback = PM2 point at previous release directory + IIS site root switch; keep `data/public` shared across releases.

## 8. Fresh Windows Server rebuild checklist (summary)

1. Install Node 20.x LTS (+ build tools), PM2 (`npm i -g pm2`), MySQL 8, Redis (Windows port or remote), IIS with URL Rewrite + ARR.
2. Clone/checkout the accepted commit (see R2.2 gate script).
3. `npm ci` (clean install), place `.env` (see R2.3 manifest).
4. `npm run build` (includes deployment verification).
5. `drizzle-kit migrate` **only** when authorised (see R2.4 rehearsal).
6. `pm2 start dist/boot.js --name natforgeai`; if Redis: `pm2 start dist/worker.js --name natforgeai-worker`; `pm2 save`.
7. IIS site → `dist/public`, apply `public/web.config`; bind 443.
8. Health verification per §6.
