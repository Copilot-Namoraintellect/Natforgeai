## Rehearsal procedure (when a disposable MySQL target exists)

```powershell
# 1. Prepare a THROWAWAY target: local MySQL in Docker, a VM snapshot, or a
#    fresh schema on a non-production host. Never the .env DATABASE_URL host.
# 2. Integrity + apply + parity (the script re-checks integrity by default):
powershell -File scripts/deployment/migration-rehearsal.ps1 `
  -TargetUrl "mysql://rehearsal:rehearsal@127.0.0.1:3306/rehearsal_throwaway" `
  -AcknowledgeDisposableTarget
# 3. Critical checks against the rehearsed schema:
$env:DATABASE_URL = "<same disposable url>"
npm run check
npx vitest run api/lib/workflow api/lib/learning api/lib/billing
# 4. Dispose: drop the schema / destroy the container or VM snapshot.
```

Safety properties: dry (no `-TargetUrl`) runs verify integrity and stop
before execution (exit 2); the script **refuses** any `-TargetUrl` equal to
the `.env` `DATABASE_URL` and refuses to run without
`-AcknowledgeDisposableTarget`; every phase fails closed.

## Rollback / recovery guidance

- **Rehearsal target**: no rollback needed — drop the schema or restore the
  disposable snapshot; nothing production-adjacent is written.
- **Future production application** (requires separate authority): apply the
  same 27-migration chain with `drizzle-kit migrate`; rollback = restore the
  pre-migration database backup (migrations are forward-only; there is no
  down-chain). Verify with the same parity probe pointed at the production
  read-replica/backup before traffic is enabled.
